Android ViewModel

Use Cases, Patterns & Best Practices

Kotlin Implementation Guide • 2026

What is ViewModel?

  • Lifecycle-aware component for managing UI-related data
  • Survives configuration changes (screen rotation, language change)
  • Separates business logic from UI components
  • Part of Android Jetpack Architecture Components

Why Use ViewModel?

  • Prevents data loss during configuration changes
  • Reduces memory leaks by avoiding Activity/Fragment references
  • Enables reactive programming with LiveData/Flow
  • Improves testability and code maintainability

ViewModel Lifecycle

ViewModel lives longer than Activity/Fragment lifecycle

Activity Lifecycle

onCreate → onDestroy (multiple times on rotation)

ViewModel Lifecycle

Created once → Survives rotation → onCleared on finish

Use Case 1: Configuration Change Survival

Preserve data during screen rotation

class CounterViewModel : ViewModel() {
    private val _count = MutableLiveData(0)
    val count: LiveData<Int> = _count
    
    fun increment() {
        _count.value = (_count.value ?: 0) + 1
    }
}

Use Case 1: Activity Implementation

class MainActivity : AppCompatActivity() {
    private val viewModel: CounterViewModel by viewModels()
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        viewModel.count.observe(this) { count ->
            textView.text = count.toString()
        }
        
        button.setOnClickListener { viewModel.increment() }
    }
}

Use Case 2: Data Persistence with Repository

ViewModel communicates with Repository for data operations

class UserViewModel(
    private val repository: UserRepository
) : ViewModel() {
    private val _users = MutableLiveData<List<User>>()
    val users: LiveData<List<User>> = _users
    
    fun loadUsers() {
        viewModelScope.launch {
            _users.value = repository.getUsers()
        }
    }
}

Use Case 3: Network Operations

Handle API calls with loading states

class NewsViewModel : ViewModel() {
    private val _uiState = MutableStateFlow<UiState>(UiState.Loading)
    val uiState: StateFlow<UiState> = _uiState
    
    fun fetchNews() = viewModelScope.launch {
        _uiState.value = UiState.Loading
        try {
            val news = repository.getNews()
            _uiState.value = UiState.Success(news)
        } catch (e: Exception) {
            _uiState.value = UiState.Error(e.message)
        }
    }
}

Use Case 4: Shared ViewModel Between Fragments

Share data between multiple fragments

// Fragment A
class FragmentA : Fragment() {
    private val sharedVM: SharedViewModel by activityViewModels()
    
    fun sendData() {
        sharedVM.updateMessage("Hello from Fragment A")
    }
}

// Fragment B
class FragmentB : Fragment() {
    private val sharedVM: SharedViewModel by activityViewModels()
    
    override fun onViewCreated(view: View, state: Bundle?) {
        sharedVM.message.observe(viewLifecycleOwner) { msg ->
            textView.text = msg
        }
    }
}

Use Case 5: Form Validation

Manage form state and validation logic

class LoginViewModel : ViewModel() {
    val email = MutableLiveData<String>()
    val password = MutableLiveData<String>()
    
    val isValid: LiveData<Boolean> = MediatorLiveData<Boolean>().apply {
        addSource(email) { validate() }
        addSource(password) { validate() }
    }
    
    private fun validate() {
        val emailValid = email.value?.contains("@") == true
        val passValid = (password.value?.length ?: 0) >= 6
        isValid.value = emailValid && passValid
    }
}

Use Case 6: Coroutines with ViewModelScope

Automatic cancellation when ViewModel is cleared

class SearchViewModel : ViewModel() {
    private val _results = MutableStateFlow<List<Item>>(emptyList())
    val results: StateFlow<List<Item>> = _results
    
    fun search(query: String) = viewModelScope.launch {
        delay(300) // Debounce
        _results.value = repository.search(query)
    }
    
    // Automatically cancelled when ViewModel is cleared
}

Use Case 7: Process Death Survival

SavedStateHandle persists data during process death

class DetailViewModel(
    private val savedStateHandle: SavedStateHandle
) : ViewModel() {
    
    var selectedId: String?
        get() = savedStateHandle["selected_id"]
        set(value) { savedStateHandle["selected_id"] = value }
    
    fun loadDetails(id: String) {
        selectedId = id // Survives process death
        // Load data...
    }
}

ViewModel Factory (Constructor Injection)

class UserViewModelFactory(
    private val repository: UserRepository
) : ViewModelProvider.Factory {
    override fun <T : ViewModel> create(modelClass: Class<T>): T {
        if (modelClass.isAssignableFrom(UserViewModel::class.java)) {
            return UserViewModel(repository) as T
        }
        throw IllegalArgumentException("Unknown ViewModel")
    }
}

// Usage
val viewModel: UserViewModel by viewModels { 
    UserViewModelFactory(repository) 
}

↔

Data source abstraction

LiveData vs StateFlow

LiveData

  • Lifecycle-aware by default
  • Android-specific
  • No initial value required

StateFlow

  • Kotlin Coroutines-based
  • Platform-independent
  • Requires initial value

Best Practices (Part 1)

  • Never pass Activity/Fragment context to ViewModel
  • Use ViewModelScope for coroutines
  • Expose immutable data (LiveData/StateFlow)
  • Keep ViewModels independent of Android framework

Best Practices (Part 2)

  • Inject dependencies via constructor or Factory
  • Use Repository pattern for data layer separation
  • Handle resource cleanup in onCleared()
  • Test ViewModel logic with unit tests

Common Pitfalls to Avoid

  • Storing Activity/Fragment references (causes leaks)
  • Heavy operations in ViewModel constructor
  • Exposing mutable LiveData/StateFlow publicly
  • Business logic in Activity/Fragment instead of ViewModel

ViewModel Scope Comparison

viewModels()

Scoped to Fragment or Activity

activityViewModels()

Shared across all Fragments in Activity

Real Example: E-commerce Cart

class CartViewModel : ViewModel() {
    private val _items = MutableStateFlow<List<CartItem>>(emptyList())
    val items: StateFlow<List<CartItem>> = _items
    
    val totalPrice: StateFlow<Double> = items.map { items ->
        items.sumOf { it.price * it.quantity }
    }.stateIn(viewModelScope, SharingStarted.Lazily, 0.0)
    
    fun addItem(item: CartItem) {
        _items.value = _items.value + item
    }
    
    fun removeItem(itemId: String) {
        _items.value = _items.value.filter { it.id != itemId }
    }
}
