Android Lifecycle-Aware Components

Building Cleaner, Maintainable Android Apps

Android Jetpack Architecture Components

What Are Lifecycle-Aware Components?

  • Components that automatically respond to lifecycle changes
  • Part of Android Jetpack Architecture Components
  • Move lifecycle-dependent code out of Activities/Fragments
  • Reduce memory leaks and crashes

The Problem (Traditional Approach)

  • Lifecycle logic scattered in Activity/Fragment methods
  • Manual start/stop calls in onCreate, onResume, onPause
  • Easy to forget cleanup leading to memory leaks
  • Poor separation of concerns

Key Components

Lifecycle

Holds lifecycle state of a component

LifecycleOwner

Interface that owns a lifecycle (Activity, Fragment)

Key Components (Continued)

LifecycleObserver

Interface for observing lifecycle events

DefaultLifecycleObserver

Modern interface with explicit callback methods

Lifecycle Events

  • ON_CREATE - Component created
  • ON_START - Component visible
  • ON_RESUME - Component interactive
  • ON_PAUSE - Component losing focus
  • ON_STOP - Component no longer visible
  • ON_DESTROY - Component destroyed

Real-World Example: Location Tracker

A location tracking manager that needs to:

  • Start location updates when Activity is visible
  • Stop updates when Activity is paused
  • Clean up resources when destroyed

Traditional Approach (Bad)

class MainActivity : AppCompatActivity() {
    private lateinit var locationManager: LocationManager
    
    override fun onResume() {
        super.onResume()
        locationManager.startLocationUpdates()
    }
    
    override fun onPause() {
        super.onPause()
        locationManager.stopLocationUpdates()
    }
}

Problem: Lifecycle logic coupled with Activity

Lifecycle-Aware Approach (Good)

class MainActivity : AppCompatActivity() {
    private lateinit var locationManager: MyLocationObserver
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        locationManager = MyLocationObserver(this)
        lifecycle.addObserver(locationManager)
    }
}

Component manages its own lifecycle automatically

Kotlin: LocationObserver Implementation

class MyLocationObserver(
    private val context: Context
) : DefaultLifecycleObserver {
    
    private var locationManager: LocationManager? = null
    
    override fun onCreate(owner: LifecycleOwner) {
        locationManager = context.getSystemService(
            Context.LOCATION_SERVICE
        ) as LocationManager
    }
}

Kotlin: Lifecycle Methods

override fun onResume(owner: LifecycleOwner) {
    startLocationUpdates()
}

override fun onPause(owner: LifecycleOwner) {
    stopLocationUpdates()
}

override fun onDestroy(owner: LifecycleOwner) {
    locationManager = null
}

Kotlin: Complete LocationObserver

class MyLocationObserver(
    private val context: Context,
    private val callback: (Location) -> Unit
) : DefaultLifecycleObserver {
    
    private var locationManager: LocationManager? = null
    
    private val locationListener = LocationListener {
        callback(it)
    }
}

Kotlin: Start and Stop Updates

private fun startLocationUpdates() {
    if (hasLocationPermission()) {
        locationManager?.requestLocationUpdates(
            LocationManager.GPS_PROVIDER,
            5000L, 10f, locationListener
        )
    }
}

private fun stopLocationUpdates() {
    locationManager?.removeUpdates(locationListener)
}

Kotlin: Using in Activity

class MainActivity : AppCompatActivity() {
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)
        
        val observer = MyLocationObserver(this) { location ->
            updateUI(location)
        }
        lifecycle.addObserver(observer)
    }
}

Java: LocationObserver Implementation

public class MyLocationObserver 
    implements DefaultLifecycleObserver {
    
    private Context context;
    private LocationManager locationManager;
    private LocationCallback callback;
    
    public MyLocationObserver(Context context, 
                             LocationCallback callback) {
        this.context = context;
        this.callback = callback;
    }
}

Java: Lifecycle Methods

@Override
public void onCreate(@NonNull LifecycleOwner owner) {
    locationManager = (LocationManager) 
        context.getSystemService(Context.LOCATION_SERVICE);
}

@Override
public void onResume(@NonNull LifecycleOwner owner) {
    startLocationUpdates();
}

Java: Using in Activity

public class MainActivity extends AppCompatActivity {
    
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);
        
        MyLocationObserver observer = 
            new MyLocationObserver(this, location -> {
                updateUI(location);
            });
        getLifecycle().addObserver(observer);
    }
}

Benefits of Lifecycle-Aware Components

  • Clean separation of concerns
  • Reduced boilerplate in Activities/Fragments
  • Automatic cleanup prevents memory leaks
  • Reusable components across multiple screens
  • Easier testing and maintenance

Best Practices

  • Keep UI controllers lean - delegate to observers
  • Use viewLifecycleOwner in Fragments for View observation
  • Combine with ViewModel for complete architecture
  • Avoid holding Activity/View references in observers
